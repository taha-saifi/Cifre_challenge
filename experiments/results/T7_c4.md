# CVE-2026-63520 — Arbitrage gravité CVSS élevée vs probabilité d'exploitation faible

## Décision

**Corriger en urgence : appliquer les correctifs SharePoint disponibles sous 7 jours (fenêtre d'exception, sans attendre le cycle de patching mensuel), en traitant l'EPSS faible comme non décisif dans ce cas précis.**

## Justification

### 1. L'EPSS « faible » est un faux signal de faible risque ici

- La probabilité EPSS observée au 2026-08-28 est de **0,0289 (2,89 %)**, ce qui paraît négligeable en valeur absolue.
- Mais le **percentile associé est 0,8586** : cette vulnérabilité est plus « exploitable-probable » que ~86 % de toutes les CVE référencées. L'échelle EPSS étant fortement asymétrique, 2,89 % est en réalité un score haut du parc.
- L'EPSS mesure la probabilité d'exploitation observée dans les 30 jours, sur des signaux publics. Sur une CVE **publiée le 2026-08-11** et analysée le 2026-08-13, la fenêtre d'observation est trop courte : le score reflète surtout l'absence d'historique, pas l'absence de risque.

Conclusion partielle : l'EPSS ne justifie pas de dégrader la priorité.

### 2. Les signaux qualitatifs pointent tous dans le sens opposé à l'EPSS

- **MSRC : « Exploitation More Likely »** — c'est l'évaluation d'exploitabilité de l'éditeur lui-même, et elle contredit directement la lecture rassurante de l'EPSS. Elle prime, car elle est fondée sur l'analyse du code corrigé.
- **Rapid7 a publié les détails techniques en avance sur le calendrier** (« ahead of schedule ») et qualifie le problème d'« unsafe ». La disponibilité publique de détails techniques est le principal accélérateur du passage à un exploit fonctionnel — c'est précisément le facteur que l'EPSS n'a pas encore eu le temps d'intégrer.
- **Chaînabilité** : la CVE est explicitement chaînable à une vulnérabilité de contournement d'authentification, et le sous-graphe rapporte un enchaînement avec CVE-2026-55040 conduisant à une **exécution de code à distance non authentifiée** sur un serveur SharePoint vulnérable. La complexité d'attaque élevée (AC:H) qui abaisse le score isolé de cette CVE est **annulée par le chaînage** : le prérequis difficile est fourni par la vulnérabilité amont.
- **Structure similaire à des vulnérabilités connues** (S10) : la réutilisation de schémas d'exploitation existants raccourcit encore le délai d'armement.

### 3. Le profil d'impact ne laisse pas de marge

- Vecteur **CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H**, base score **8,1 (HIGH)**, impact score **5,9** (maximum pour un scope UNCHANGED).
- **AV:N + PR:N + UI:N** : exploitable à distance, sans authentification et sans action utilisateur. Seul AC:H freine — et ce frein tombe en cas de chaînage (point 2).
- **SSVC technicalImpact = total** : compromission complète du composant. CWE-20 (validation d'entrée) menant à de l'exécution de code.
- Produits touchés : **SharePoint Enterprise Server 2016, SharePoint Server 2019, SharePoint Server Subscription Edition** — plateformes collaboratives, typiquement exposées et riches en données métier, souvent point d'appui pour un mouvement latéral.

### 4. Ce qui tempère, et pourquoi cela ne change pas la décision

Éléments à décharge, à mentionner honnêtement :

- **SSVC exploitation = none** : aucune exploitation active constatée à la date des données.
- **SSVC automatable = no** : pas d'exploitation de masse automatisable — le risque est celui d'une attaque ciblée, pas d'un ver.
- **MSRC publiquement divulgué = No**, **MSRC exploité = No**.

Ces éléments justifient de **ne pas déclencher une procédure d'incident ni un arrêt de production** (pas de correctif « dans l'heure »). Ils ne justifient pas d'attendre : « pas encore exploité » décrit un état à une date, pas une tendance, et il est contredit par « Exploitation More Likely » + détails techniques publics.

### 5. Le facteur décisif : le coût du correctif est faible et connu

Des correctifs éditeur sont **déjà disponibles et identifiés** :

| KB | Produit | Version |
|---|---|---|
| KB5002893 | SharePoint Server Subscription Edition | 16.0.19725.20522 |
| KB5002894 / KB5002896 | SharePoint Server 2019 | 16.0.10417.20198 |
| KB5002905 / KB5002906 | SharePoint Enterprise Server 2016 | 16.0.5565.1001 |

L'arbitrage gravité/probabilité n'a de sens que lorsque la remédiation est coûteuse ou risquée. Ici, la remédiation est un patch éditeur standard, testable en préproduction. **Quand le coût du correctif est bas et l'impact potentiel est total, l'incertitude sur la probabilité doit être résolue en faveur du correctif.**

## Règle d'arbitrage retenue (généralisable)

L'EPSS est un outil de **priorisation relative entre CVE**, pas un feu vert pour différer. Il ne doit abaisser l'urgence que si, cumulativement :

1. le percentile EPSS est également bas (ici : non — 0,86) ;
2. l'éditeur ne signale pas d'exploitabilité probable (ici : non — « More Likely ») ;
3. aucun détail technique ni PoC n'est public (ici : non — Rapid7) ;
4. la CVE n'est pas chaînable pour contourner son propre prérequis d'attaque (ici : non — chaînage avec bypass d'authentification / CVE-2026-55040) ;
5. le correctif est coûteux ou indisponible (ici : non — 5 KB disponibles).

Aucun des cinq critères n'est satisfait. **La gravité l'emporte.**

## Limites de l'analyse

- Décision fondée uniquement sur le sous-graphe KG fourni (sources S06, S10, S18, S25, S41, S42) ; l'EPSS est daté du 2026-08-28 et doit être réévalué.
- L'exposition réelle (nombre d'instances, exposition Internet, criticité des données hébergées) n'est pas dans le contexte : elle peut resserrer le délai de 7 jours, jamais l'allonger.
