# T6 — c5 : Priorisation des cinq CVE du périmètre

## Classement (du plus urgent au moins urgent)

1. **CVE-2026-55040** — SharePoint, contournement d'authentification (JWT forgé), CVSS 9.1
2. **CVE-2026-59310** — VMware vCenter, directory traversal → RCE non authentifiée, CVSS 9.8
3. **CVE-2026-33824** — Windows IKE Extension, double free → RCE réseau, CVSS 9.8
4. **CVE-2026-65400** — macOS Screen Sharing, contournement d'authentification, CVSS 9.8
5. **CVE-2026-63520** — SharePoint, validation d'entrée insuffisante → RCE, CVSS 8.1

---

## Justification

### Critères de tri retenus

Le CVSS base score seul ne discrimine pas ici (quatre CVE sur cinq sont CRITICAL, dont
trois à 9.8 avec un vecteur strictement identique `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`).
Le tri s'appuie donc, dans cet ordre, sur :

1. **Exploitation réelle constatée** (SSVC `exploitation`, présence au catalogue CISA KEV,
   preuves d'exploitation dans les sources) ;
2. **Disponibilité et maturité d'un exploit public** (PoC publié, PoC observé en usage) ;
3. **Effet de levier du correctif** (une CVE dont le patch casse une chaîne d'attaque
   complète prime sur une CVE isolée de score équivalent) ;
4. **Probabilité d'exploitation EPSS** (percentiles au 2026-08-28) ;
5. **Rayon d'impact / criticité de l'actif** (plan de contrôle vs poste de travail).

Point commun à noter d'emblée : **quatre CVE sur cinq (33824, 55040, 59310, 65400) sont
inscrites au KEV le 2026-08-18 avec une échéance CISA au 2026-08-21**. Cette échéance est
**dépassée** à la date d'analyse (2026-08-29) : ces quatre correctifs sont en retard, le
classement ci-dessous ordonne un rattrapage, pas un délai confortable.

---

### 1. CVE-2026-55040 (SharePoint, bypass d'authentification) — le plus urgent

Ce n'est pas la CVE au score le plus élevé (9.1, disponibilité non impactée), et c'est
pourtant celle qu'il faut corriger en premier, pour trois raisons cumulées :

- **Exploit public, armé et déjà employé.** Rapid7 (Stephen Fewer) a publié un PoC
  (`github.com/sfewer-r7/CVE-2026-55040`) *et* les détails techniques complets. La firme
  Defused signale que des attaquants utilisent ce PoC de Rapid7 contre des honeypots
  SharePoint. On n'est donc pas sur une exploitation potentielle mais sur un exploit
  commodifié, à la portée d'attaquants opportunistes.
- **Effet de levier maximal sur la chaîne d'attaque.** Le contournement d'authentification
  permet à un attaquant non authentifié d'agir comme utilisateur du site *ou comme
  administrateur*, et chaîné à CVE-2026-63520 il donne une **exécution de code à distance
  non authentifiée** sur le serveur SharePoint. Les sources sont explicites :
  *« Patching CVE-2026-55040 break exploit chain »*. Corriger cette seule CVE désamorce
  également le risque principal porté par la n°5 du classement.
- **Correctif identifié et applicable immédiatement** : KB5002891 (SE 2016), KB5002883
  (Server 2019), KB5002882 (Subscription Edition).

EPSS au 98,6e percentile, SSVC `exploitation: active`, `automatable: yes`,
`technicalImpact: total`. KEV, échéance dépassée.

### 2. CVE-2026-59310 (VMware vCenter) — exploitation de masse avérée

- **Exploitation massive et documentée** : 361 IP victimes recensées dans 47 pays, campagne
  attribuée à un APT suspecté d'origine chinoise, exploitation également liée à
  CVE-2026-59309. SSVC `exploitation: active`, `automatable: yes`, KEV.
- **RCE non authentifiée sur le plan de contrôle de la virtualisation** : traversée de
  répertoires dans le serveur Syslog (CWE-22), sans identifiants ni interaction
  utilisateur, sur vCenter / Cloud Foundation / vSphere Foundation / Telco Cloud. La
  compromission de vCenter, c'est la compromission de l'ensemble des machines virtuelles
  hébergées : le rayon d'impact dépasse largement celui d'un serveur applicatif.
- EPSS au 98,75e percentile (le 2e du lot), CVSS 9.8 avec impact total C/I/A.
- Avis éditeur disponible : VMSA-2026-0006 (Broadcom).

Elle passe derrière 55040 uniquement parce qu'aucun correctif n'est nommé dans le
sous-graphe (seul l'avis l'est) et parce que corriger 55040 neutralise deux CVE d'un coup ;
si vCenter est exposé à Internet dans le périmètre réel, cette CVE peut légitimement
repasser en n°1.

### 3. CVE-2026-33824 (Windows IKE Extension)

- **EPSS le plus élevé du lot** : 99,42e percentile. SSVC `active` / `automatable: yes` /
  `technicalImpact: total`, KEV. CVSS 9.8, double free (CWE-415) exploitable en RCE réseau
  sans authentification.
- **Surface d'exposition la plus large** : toutes les versions de Windows 10 et 11
  supportées, et Windows Server 2016 à 2025, y compris les installations Server Core.
- Elle est référencée dans une campagne d'attaque « autonomous AI » (Unit 42), et
  Microsoft a publié les mises à jour de sécurité.

Le facteur qui la place en 3e position plutôt qu'en 1re est une **condition d'exploitation
plus restrictive** : la capacité attaquante requise est explicitement *« ability to send
specially crafted IKE traffic to a vulnerable system »*. Le service IKE/IPsec n'est pas
exposé par défaut sur l'ensemble du parc — seuls les hôtes acceptant du trafic IKE
(passerelles VPN, extrémités IPsec) sont réellement atteignables. Le nombre de machines
*vulnérables* est énorme, mais le nombre de machines *exposées* est bien plus réduit que
pour un vCenter ou un SharePoint publiés. À nuancer selon l'inventaire réel : si des
passerelles VPN Windows sont en frontal Internet, elle remonte en n°2.

### 4. CVE-2026-65400 (macOS Screen Sharing)

Elle coche les mêmes cases de gravité que les précédentes — CVSS 9.8, KEV, SSVC `active` /
`automatable: yes` / `technicalImpact: total`, authentification contournable sans
identifiants valides (CWE-287) par un attaquant sur le réseau — mais elle arrive 4e :

- **EPSS le plus bas des quatre CVE du KEV** (95,29e percentile contre 98,5–99,4 pour les
  autres) : probabilité d'exploitation relativement plus faible.
- **Actif moins critique et exposition plus faible** : macOS postes de travail plutôt que
  serveur ou plan de contrôle ; le service Screen Sharing est rarement publié sur Internet
  et l'attaque suppose une position réseau (souvent LAN). Le mouvement latéral reste le
  scénario principal, ce qui la rend dangereuse mais en second temps d'une intrusion.
- **Correctifs disponibles et bien identifiés** : macOS Sequoia 15.7.9, Sonoma 14.8.9,
  Tahoe 26.6.1 — remédiation simple si un MDM pilote le parc.

Elle reste dans le lot « en retard sur l'échéance CISA du 2026-08-21 » : 4e ne veut pas
dire « plus tard dans le trimestre ».

### 5. CVE-2026-63520 (SharePoint, RCE) — la moins urgente

Seule CVE du périmètre **hors KEV**, et la seule dont les indicateurs d'exploitation sont
au vert :

- **SSVC `exploitation: none` et `automatable: no`** — aucune exploitation constatée, contre
  `active`/`yes` pour les quatre autres.
- **Complexité d'attaque HIGH** (`AC:H`), d'où un score de 8.1 (HIGH, pas CRITICAL) et un
  **sous-score d'exploitabilité de 2,2 contre 3,9** pour toutes les autres — c'est l'écart
  le plus net du lot.
- **EPSS le plus bas** : 85,86e percentile.
- Aucune échéance CISA opposable.

Deux nuances qui interdisent de la classer « à ignorer » : Microsoft l'évalue
*« Exploitation More Likely »*, et Rapid7 en a publié les détails techniques *en avance sur
le calendrier prévu* — la fenêtre avant apparition d'un exploit public peut se refermer
vite. Surtout, elle est **le second maillon de la chaîne portée par CVE-2026-55040** :
c'est la désérialisation qui, une fois l'authentification contournée, donne la RCE.

**Conséquence opérationnelle** : elle est dernière en priorité *propre*, mais elle se
corrige en pratique dans la même fenêtre que la n°1, puisque les deux touchent les mêmes
serveurs SharePoint (SE 2016, Server 2019, Subscription Edition) et que les correctifs
existent des deux côtés (KB5002905/KB5002906, KB5002894/KB5002896, KB5002893 pour 63520).
Traiter les deux dans la même opération de patching évite un second arrêt de service.

## Limites de cette analyse

- Le sous-graphe est explicitement **incomplet** ; le classement s'appuie uniquement sur les
  faits qu'il contient.
- **Aucune information d'inventaire ni d'exposition réelle** n'est disponible : le nombre
  d'actifs concernés par CVE et leur exposition Internet ne figurent pas dans le contexte.
  Or CISA rappelle dans l'action requise que *« Stakeholders are responsible for evaluating
  each asset's internet exposure »*. Un rapprochement avec l'inventaire du parc peut
  légitimement réordonner les rangs 2 à 4 (un vCenter ou une passerelle IKE en frontal
  Internet prime sur tout le reste ; à l'inverse, l'absence de SharePoint dans le parc
  annule le rang 1).
- Les scores EPSS sont des **percentiles** au 2026-08-28, pas des probabilités brutes.
- Pour CVE-2026-59310, aucune version corrigée précise n'apparaît dans le sous-graphe
  (seulement l'avis VMSA-2026-0006) : la version cible reste à confirmer auprès de Broadcom.
- Certaines assertions du sous-graphe sont issues d'une extraction OpenIE au phrasé dégradé
  (ex. « we know similar structure to CVE-2026-63520 », « pairing with CVE-2026-55040 …
  we_achieved fully authenticated deserialization ») ; elles ont été utilisées uniquement
  comme faisceau d'indices convergents sur l'existence de la chaîne 55040 → 63520, corroboré
  par l'assertion explicite « CVE-2026-63520 be_chained_to authentication bypass
  vulnerability » et par « Patching CVE-2026-55040 break exploit chain ».
