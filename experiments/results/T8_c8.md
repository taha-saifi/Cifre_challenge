# CVE-2026-63520 — Un correctif éditeur est-il disponible ?

## Conclusion

**Non déterminable en l'état : les informations disponibles ne permettent pas de confirmer la disponibilité d'un correctif éditeur pour CVE-2026-63520, et aucune référence précise de correctif (numéro de KB, bulletin de sécurité, version corrigée) n'y figure.**

## Justification

### Ce que les sources indiquent effectivement

- Le sous-graphe fourni est explicitement signalé comme **incomplet**, et il se termine par une note d'incertitude assumée : « la disponibilité d'un correctif éditeur pour CVE-2026-63520 n'a pas pu être confirmée avec certitude dans les sources disponibles ».
- Le seul élément qui évoque une remédiation est l'assertion `updates be_remediate CVE-2026-63520` (source S41). Cette assertion est **non qualifiée** : le sujet « updates » est générique, sans éditeur nommé, sans identifiant de mise à jour, sans date de publication et sans produit ciblé. Elle ne suffit donc pas à établir qu'un correctif est publié et disponible, et encore moins à en donner la référence.
- La référence `https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-63520` (S06) est un **lien vers la fiche MSRC**, c'est-à-dire le point d'entrée où un correctif serait publié. La présence d'un lien vers l'Update Guide n'est pas en soi la preuve qu'un correctif y est publié, et le sous-graphe ne contient aucune assertion extraite de cette page qui mentionnerait une KB ou une version corrigée.

### Ce qui manque pour conclure positivement

Aucune assertion du sous-graphe ne porte les éléments qui constitueraient une réponse « précise » :

- pas de numéro de KB (type `KB50xxxxx`) ;
- pas de référence de bulletin/mise à jour mensuelle (Patch Tuesday) associée ;
- pas de relation du type `has_patch`, `fixed_in_version`, `has_remediation`, ni de date de correctif ;
- pas de version corrigée pour les produits affectés listés (SharePoint Enterprise Server 2016, SharePoint Server 2019, SharePoint Server Subscription Edition).

### Éléments de contexte qui rendent un correctif plausible mais non prouvé

Plusieurs signaux indiquent une vulnérabilité prise en charge par l'éditeur, sans pour autant valoir preuve de correctif :

- l'identifiant source est `secure@microsoft.com` et le statut NVD est `Analyzed`, ce qui traduit une CVE pleinement instruite ;
- des métadonnées MSRC sont présentes (`publicly_disclosed: No`, `exploited: No`, `exploitability_assessment: Exploitation More Likely`), donc l'éditeur a bien publié une fiche ;
- la sévérité est élevée (CVSS 3.1 base 8.1, HIGH, AV:N / PR:N / UI:N, RCE non authentifiée sur SharePoint), avec un risque aggravé par le chaînage signalé avec une vulnérabilité de contournement d'authentification (`be_chained_to authentication bypass vulnerability`, S41) et le lien avec CVE-2026-55040 (S18) ;
- Rapid7 a publié des détails techniques « ahead of schedule » (S41), ce qui, en pratique, suggère un contexte de divulgation tendu autour d'une remédiation attendue.

Ces éléments justifient un traitement en urgence, mais **rien dans le corpus n'atteste ni la publication ni la référence du correctif**.

### Position retenue

Conformément au principe de ne rien affirmer sans preuve dans la source, la réponse correcte est de signaler la lacune plutôt que d'inférer une KB plausible. Fabriquer un numéro de KB à partir du seul lien MSRC serait une extrapolation non fondée.

**Action recommandée pour lever le doute :** consulter directement la fiche MSRC Update Guide de CVE-2026-63520 (lien ci-dessus) pour relever, par produit affecté, le numéro de KB et la version corrigée — puis réinjecter ces faits dans le graphe avec leur `source_id` et leur évidence verbatim.
