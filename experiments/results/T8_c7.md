# CVE-2026-63520 — Un correctif éditeur est-il disponible, et sous quelle référence ?

## Conclusion

Les informations disponibles indiquent qu'un correctif éditeur existe très probablement (Microsoft), mais **aucune référence précise de correctif (numéro de KB, identifiant de mise à jour, version corrigée ou date de Patch Tuesday) n'est présente dans le contexte fourni** : il est donc impossible d'énoncer la référence exacte sans une source complémentaire (bulletin MSRC / Microsoft Update Guide de la CVE).

## Justification

**Ce qui, dans les données, plaide pour l'existence d'un correctif :**

- `updates be_remediate CVE-2026-63520` [S41] — assertion explicite que des mises à jour corrigent la vulnérabilité. C'est le seul élément direct sur la remédiation, mais il est formulé de manière générique (« updates »), sans nommer le paquet, la build ni l'article KB.
- `CVE-2026-63520 has_source_identifier secure@microsoft.com` [S06] : la CVE est publiée par Microsoft en tant que CNA, ce qui implique normalement un avis MSRC accompagné de mises à jour de sécurité.
- Présence d'une évaluation MSRC (`has_MSRC_exploitability_assessment Exploitation More Likely`, `has_MSRC_publicly_disclosed_status No`, `has_MSRC_exploited_status No`) [S42] : ces champs proviennent d'une fiche du Microsoft Update Guide, qui n'est publiée qu'avec la diffusion des correctifs correspondants.
- `has_vulnerability_status Analyzed` [S06] avec une date de publication au 2026-08-11 et une dernière modification au 2026-08-13 : le cycle NVD est achevé, ce qui est cohérent avec une divulgation coordonnée accompagnée de correctifs.

**Ce qui manque pour donner une référence précise :**

- Aucune assertion du sous-graphe ne porte un numéro d'article KB (type `KB50xxxxx`), un identifiant de mise à jour cumulative, un numéro de build corrigé, ni une URL de bulletin.
- Les produits affectés sont listés (Microsoft SharePoint Enterprise Server 2016, SharePoint Server 2019, SharePoint Server Subscription Edition) [S06] mais sans version ou build corrigée en regard — or, pour SharePoint, chaque édition reçoit typiquement un KB distinct. Même en supposant un correctif unique, on ne peut pas déduire trois références à partir des seules lignes disponibles.
- Le contexte est explicitement un **sous-graphe canonique en état pré-validation** : l'absence d'une relation de type « corrigé par » peut aussi bien traduire une lacune d'extraction qu'une absence réelle d'information dans le corpus. Cette absence ne doit donc pas être interprétée comme « pas de correctif ».

**Éléments de contexte aggravants (ils ne changent pas la conclusion mais justifient l'urgence de la vérification) :**

- Sévérité HIGH, score CVSS 8.1, vecteur `CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H` : exécution de code à distance, sans authentification ni interaction utilisateur, impact total (C/I/A HIGH) [S06].
- `CVE-2026-63520 be_chained_to authentication bypass vulnerability` [S41] et `CVE-2026-55040 lead_to_unauthenticated_remote_code_execution_against_vulnerable_SharePoint_server CVE-2026-63520` [S18] : la complexité d'attaque HIGH, seul facteur atténuant du score, est susceptible d'être annulée par un enchaînement avec un contournement d'authentification.
- `Rapid7 publishes technical details for CVE-2026-63520 ahead of schedule` [S41] et `Rapid7 has_disclosure_for CVE-2026-63520` [S10] : des détails techniques sont publics, ce qui réduit la fenêtre avant exploitation.
- EPSS au 2026-08-28 : probabilité 0,02893 pour un percentile 0,85861 [S25] — probabilité absolue faible mais dans le décile supérieur du parc, en hausse de risque cohérente avec `Exploitation More Likely`.

**Recommandation d'action :** consulter directement la fiche Microsoft Update Guide de CVE-2026-63520 pour relever les numéros KB par édition SharePoint (2016 / 2019 / Subscription Edition), plutôt que de déduire une référence à partir de ce sous-graphe. En attendant, traiter la vulnérabilité comme non corrigée sur le parc et privilégier les mesures compensatoires (restriction de l'exposition réseau des serveurs SharePoint).
